A guided support assistant for field technicians. The technician picks a **Client** and a **Machine/Line**; the agent
retrieves context only from that machine's manuals, reasons over it with Claude, and either answers with sources
(title + page) or asks one clarifying question. Design decisions, and where the build deviates from the original
spec, are in `docs/decisions/`.

```
frontend/       React 18 + Vite + TypeScript
backend/        FastAPI, SQLAlchemy 2, Alembic, agent state machine, scope-enforced retrieval
docs/           decisions (ADRs)
scripts/        make_sample_corpus.py: generates the synthetic demo manuals
sample_corpus/  synthetic manuals: two fictional clients, three machines/lines  (generated, safe to commit)
.env            CLAUDE_API_KEY (git-ignored; copy .env.example)
```

## Run it

Prerequisites: Docker Desktop and a Claude API key.

```bash
cp .env.example .env                 # then set CLAUDE_API_KEY in .env
docker compose up --build            # postgres + cognito emulator + backend + frontend  ->  http://localhost:5173
```

The first start downloads the embedding model (~220 MB) into a Docker volume. The repository ships a **synthetic**
corpus in `sample_corpus/` (regenerate it with `make sample-corpus`). Index a client once (resumable, idempotent by
sha256, safe to interrupt):

```bash
cd backend
python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"      # Windows; use .venv/bin on macOS/Linux
.venv/Scripts/python -m app.cli.onboard "../sample_corpus/Acme Laundry Services" --dry-run   # print the plan first
.venv/Scripts/python -m app.cli.onboard "../sample_corpus/Acme Laundry Services"
```

Or, with no Python on the host, index from inside the running backend container (the corpus is mounted at `/corpus`):

```bash
docker compose exec backend python -m app.cli.onboard "/corpus/Acme Laundry Services"
```

Indexing needs the database up. Machines become usable as their documents finish (the pop-up shows each machine's
indexed document count). The sample corpus is small; a full-size manual library takes much longer on a CPU.

The two fictional clients deliberately share an identical W-100 manual, and alarm code `E4` means different things on
the W-100 washer and the D-200 dryer, so scope isolation and the clarifying-question flow can be seen working.

## Signing in

Identity is an AWS Cognito user pool: the browser authenticates against it directly and the backend only verifies the
id token it signs. Nothing here stores a password.

Locally, `docker compose` runs a Cognito emulator (moto) and seeds it with one user per role (see
`backend/app/cli/seed_local_cognito.py`): `admin@local.test`, `tech@local.test`, `lead@local.test`,
`customer@local.test`. The password is in the seed script and works against the emulator only, which refuses to run
outside a developer machine. `COGNITO_USER_POOL_ID` and `COGNITO_CLIENT_ID` must be set or every request is a 401;
the container logs `cognito_not_configured` at startup to say so.

Users are managed in the app: sign in as an `admin` and open Admin -> Users to create, disable, reset or delete them.
That writes to the pool, not to a local table; the `app_user` row appears by itself the first time somebody signs in.

| role | granted by | can do |
|---|---|---|
| `admin` | the `admin` group in the pool | everything, including user management |
| `technician` | the `technician` group | chat, library, their own sessions |
| `customer` | the `customer` group | chat, subject to `access_expires` |

A user in no group is treated as a `technician`, the least privileged role that can still use the product.

## Tests

```bash
docker compose up -d postgres
cd backend && .venv/Scripts/python -m pytest -q
```

The suite needs no Claude key and no embedding model (scripted `FakeLLM` + hash embedder) but does need real
Postgres + pgvector: it proves the composite foreign keys, scope isolation (identical text in two machines never
crosses over), the agent scenarios (ask, answer, escalate, budget limits), the verbatim guard, auth, and that no
technician-facing response schema can carry manual content or a file path.

## Ops

- `GET /healthz`, `GET /readyz` (Postgres, pgvector, Claude key, embedder), `GET /metrics` (Prometheus).
- Every turn is stored as `agent_run` / `agent_step` / `retrieval_hit`; the admin **Traces** tab replays it.
- `python -m app.cli.purge_traces` deletes traces older than `TRACE_RETENTION_DAYS` (30). Retrieval gaps are kept.

## Configuration (env vars; see `backend/app/config.py`)

`CLAUDE_API_KEY`, `CLAUDE_MODEL` (default `claude-opus-5-5`), `EFFORT_NODES`, `EFFORT_SYNTHESIS`, `EMBEDDER`
(`fastembed` | `ollama` | `hash`), `RETRIEVAL_CONTROLLER`, `GATE_MAX_DISTANCE`, `GATE_MARGIN`, `TRACE_RETENTION_DAYS`,
`DATABASE_URL`, and `COGNITO_USER_POOL_ID` / `COGNITO_CLIENT_ID` / `COGNITO_REGION`.

## Data leaving this machine

Every turn sends the technician's message and the retrieved manual excerpts to the Claude API; the original product
requirement of no outbound calls no longer holds (see `docs/decisions/0002-build-deviations-from-prd.md`). Manuals are
never sent whole and are never returned to the technician (no file routes; response schemas are whitelists; a verbatim
guard drops copied sentences).
